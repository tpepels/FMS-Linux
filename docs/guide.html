FMS Linux Field Guide

A practical manual for turning the native Linux version of FMS into patterns, patches, variations, and live changes. The core idea is simple: every step owns its own sound.

01 / First signal

Start with a working loop

Build FMS Linux with SDL2, launch it, then press Space. The starter pattern is already voiced, so the shortest path to learning is to alter something that is playing.

Build and run

sudo apt install build-essential pkg-config libsdl2-dev
make
./fms-linux

On Fedora, install gcc-c++ make pkgconf-pkg-config SDL2-devel instead. The program opens as a native SDL desktop application; it does not need a ROM or emulator.

The first minute

  1. Run transport. Press Space to hear the starter pattern.
  2. Pick a target. Use arrows, or press 1 through 5 to jump to a track.
  3. Edit one value. Choose a parameter with [/], then use -/=.
  4. Save a useful moment. Press Ctrl + S; normal exit also saves state.
Think in events, not instruments. A trigger contains its note, level, pan, timing, and synth settings. Copying a good step is often faster than recreating a patch from zero.

02 / Grid view

Program with the grid under your hands

This miniature grid follows the same editing grammar as the app. Click a cell, or give the lab focus and use its listed keys. It is a documentation playground, not connected to a saved project.

READY. Arrows move. Enter toggles. T makes a trigless event. [/] changes parameter.

Everyday editing

  • Enter places or removes a trigger. Delete and Backspace clear it.
  • [ and ] move through step and synth parameters; Shift + -/= changes values coarsely.
  • Shift + arrows makes a rectangular selection. Press F5 to switch scope between selection, track, and all tracks.
  • C, X, and V copy, cut, and paste a step or a selected rectangle.

Time is a parameter

  • L changes the active track length. Each track can loop independently.
  • Alt + left/right changes track rate. Alt + up/down changes shuffle; add Ctrl to affect every track.
  • D cycles forward, ping-pong, reverse, and random direction. O rotates a track or range.
  • The WAIT field shifts a trigger by microticks. Negative offsets are constrained at queued pattern boundaries so a fresh pattern does not arrive early.

04 / Voice behavior

Chord, slide, and interrupt with intent

The four FM tracks share a finite FM voice pool. A step can ask for up to three chord offsets in addition to its root; a tonal arrangement stays clear when you decide which tracks deserve the available voices.

Chord fields

Choose CHD1, CHD2, or CHD3 on an FM step and enter semitone offsets relative to NOTE. A value of +7 adds a fifth; zero leaves that chord slot unused.

Trigless motion

Use T to toggle a trigless step. It updates target values without restarting oscillator phase or envelopes, which makes it useful for stepped pitch bends, level movement, and evolving modulation.

Conditional events

COND determines whether an event fires every nth count. Combine condition, microtime, and independent track length to make movement that does not reset with the main loop.

Practical chord recipe: Put a stable bass or lead on a separate FM track, then use one of the remaining tracks for chord roots and its three chord offsets. When the pool is busy, simplify the chord or leave headroom in the arrangement.

05 / Synthesis

Choose a compact voice or go deeper

FM steps begin with the original compact two-operator engine. Advanced FM is an opt-in, per-step engine, so it expands sound design without changing the rendering path of legacy sounds.

Legacy FM and noise

A.ATK / A.HLD / A.REL
Amplitude attack, hold, and release.
RATIO / M.DEP / M.FBK
Modulator ratio, depth, and feedback.
M.ATK / M.REL / M.END
Modulation envelope shape and sustain.
S.DEP / S.REL
Pitch sweep amount and fade-out.
MODE
Two-operator FM or parallel routing.
RATE / WIDTH
Noise speed and wide/narrow LFSR mode.

Parallel mode mixes the two FM operators instead of phase-modulating one with the other. Use it for detuned pairs, two-note intervals, and direct additive colors.

Advanced FM

  • Four operators with selectable sine, triangle, saw, square, pulse, or noise shapes.
  • Twelve routing algorithms, individual ratio, level, feedback, and fine detune.
  • Amp ADSR, four routed modulation slots, multimode filter, resonance, and drive.
  • One to four stereo unison voices with detune and width controls.

Open SYNTH with Tab and use Page Up/Page Down to audition neighboring steps without losing the focused field. Advanced fields work with range, track, all-track, palette, pattern, snapshot, and preview workflows.

06 / Seven places to work

Change view, keep context

Tab and Shift + Tab cycle Grid, Synth, Echo, Transpose, Mod, Scale, and Data. Each view stays tied to the active track and selected step, so sound design and sequencing remain close together.

GRID

The main pattern surface. Place triggers and edit step values, legacy patch values, track length, rate, shuffle, direction, mute, solo, and scope.

Use this for programming and fast changes while transport runs.

SYNTH

The detailed advanced FM editor. Navigate the complete field list for the selected FM step, including operators, routing, envelopes, filter, drive, unison, and modulation slots.

Use this when a step needs a deliberately designed timbre rather than a quick legacy adjustment.

ECHO

Algorithmic repeats per track. Set repeat count, spacing, transpose, volume/modulation/feedback attenuation, and echo pan behavior.

The ECHO step parameter decides whether an event sends into this track effect.

TRANSPOSE

An eight-step pitch lane. Adjust transposition values, lane length, rate, and whether it advances by pattern, step, or trigger.

The TSP step parameter controls whether a particular event receives the lane.

MOD

A step-sampled modulator. Route each track's modulation source to a target track and destination, then choose speed, shape, depth, and start offset.

It behaves like an LFO sampled at events, so polymetric clocks can create useful phase drift.

SCALE

Pitch entry and playback quantization. Choose a root and a twelve-note mask. Entered and played notes follow the current scale.

Store a scale in a bank when a recall needs to change musical context with a pattern.

DATA

Patterns, banks, and live loading. Select a slot or whole column, save, load in place, load and reset, cue, clear, randomize, rename, lock, and manage stored BPM/scale.

Use this as the performance memory and safety surface.

07 / Performance

Prepare changes before you need them

The strongest live workflow is not frantic editing. It is a small collection of variations, a snapshot for safe experiments, and queued patterns that land on a musical boundary.

Palette

Press P to open the appropriate FM or noise palette. Enter recalls a sound, Shift + Enter stores it, and Ctrl + Enter applies it across the track. Slots 0 through D persist per engine.

Snapshot

Press S to capture or recall a performance snapshot. Take one before an energetic edit, then flip between the stored state and the live state without loading a new pattern.

Pattern cue

In Data, Q queues the selected slot or column. Single-track cues land at that track's next nominal loop boundary; whole columns land atomically at the next global 16-step boundary.

A reliable variation loop

  1. Copy the current material. In Data, save a slot or a whole five-track column with Shift + Enter.
  2. Make a controlled difference. Rotate, change one parameter across a range, or use incremental R randomization.
  3. Protect the original. Capture a snapshot with S before trying aggressive sound edits.
  4. Queue the return. Select the prepared slot or column and press Q.

Mute and movement

  • M mutes the selected track; Shift + M solos it. U clears both states everywhere.
  • R nudges the selected parameter toward increasingly random values in the active scope. Shift + R makes a full random pattern for the track.
  • O rotates the active track or range. Add Ctrl to rotate every track together.
  • Use in-place loads for phase-continuous changes. Use reset loads when different lengths and rates need a clean new downbeat.

08 / State and files

Save one state well

FMS Linux keeps project state in a versioned, checksummed, atomically replaced file. A partial write cannot overwrite the last good session.

Default save location

$XDG_DATA_HOME/fms-linux/state.bin
~/.local/share/fms-linux/state.bin when XDG_DATA_HOME is unset

Use --save-path FILE to open a separate working state. This is useful for a set, an experiment, or a clean tutorial session. The header PROJECT menu exposes Start New, Clear Working Tracks, and Save Now; New and Clear require a confirmation step.

Useful command-line checks

make test
make screenshot
make audio-smoke
./fms-linux --help

make screenshot verifies the UI through SDL's dummy driver. make audio-smoke exercises the real-time engine with SDL's dummy audio driver.
